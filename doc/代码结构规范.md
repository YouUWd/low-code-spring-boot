## 分层架构说明

### 1. API 层 (config-api)

**位置**: `jdec-platform-config-api/src/main/java/com/jdec/platform/config/api/`

**职责**:
- 定义 API 接口契约
- 定义 Request/Response DTO
- 不包含业务逻辑实现

**接口列表**:
- `SysModuleApi` - 模块管理
- `SysModuleTableApi` - 模块表管理
- `SysModuleFieldApi` - 模块字段管理
- `SysPermissionConfigApi` - 权限配置管理

### 2. 业务层 (config-biz)

#### 2.1 Entity 层
**位置**: `jdec-platform-config-biz/src/main/java/com/jdec/platform/config/biz/entity/`

**职责**:
- 映射数据库表结构
- 使用 MyBatis-Plus 注解

**实体类**:
- `SysModule` - 模块基本信息
- `SysModuleTable` - 模块关联物理表
- `SysModuleField` - 模块字段配置
- `SysPermissionConfig` - 权限配置

#### 2.2 Mapper 层
**位置**: `jdec-platform-config-biz/src/main/java/com/jdec/platform/config/biz/mapper/`

**职责**:
- 数据库操作接口
- 继承 `BaseMapper<T>`
- 支持 MyBatis-Plus 的 CRUD 操作

**Mapper 接口**:
- `SysModuleMapper`
- `SysModuleTableMapper`
- `SysModuleFieldMapper`
- `SysPermissionConfigMapper`

#### 2.3 Service 层
**位置**: `jdec-platform-config-biz/src/main/java/com/jdec/platform/config/biz/service/`

**职责**:
- 实现 API 接口
- 包含业务逻辑
- 数据转换（Entity ↔ DTO）
- 事务管理

**Service 类**:
- `SysModuleService` - 实现 `SysModuleApi`
- `SysModuleTableService` - 实现 `SysModuleTableApi`
- `SysModuleFieldService` - 实现 `SysModuleFieldApi`
- `SysPermissionConfigService` - 实现 `SysPermissionConfigApi`

#### 2.4 Controller 层
**位置**: `jdec-platform-config-biz/src/main/java/com/jdec/platform/config/biz/controller/`

**职责**:
- 处理 HTTP 请求
- 注入 API 接口（不是 Service）
- 包装响应为 `ApiResponse<T>`

**Controller 类**:
- `SysModuleController` - `/api/config/modules`
- `SysModuleTableController` - `/api/config/module-tables`
- `SysModuleFieldController` - `/api/config/module-fields`
- `SysPermissionConfigController` - `/api/config/permissions`

## API 端点设计

### 模块管理 (`/api/config/modules`)

| 操作 | HTTP | 端点 | 参数 | 职责 |
|------|------|------|------|------|
| 获取列表 | GET | `/` | - | 返回项目下所有模块基本信息（通过 AppContext 获取 projectNo） |
| 完整信息 | GET | `/{moduleCode}/complete` | `moduleCode` | 返回模块及其关联表、字段的完整配置 |
| 保存/编辑 | POST | `/complete` | `SaveModuleReq` | 自动识别新增或更新。新增时从 AppContext 获取租户 ID |
| 移动模块 | POST | `/move` | `MoveModuleReq` | 更新父节点或排序（基于全局唯一 ID） |
| 删除模块 | DELETE | `/{moduleId}/complete` | `moduleId` | 级联删除模块相关所有配置（基于全局唯一 ID） |

### 模块表管理 (`/api/config/module-tables`)

| 操作 | HTTP | 端点 | 请求 | 响应 |
|------|------|------|------|------|
| 创建 | POST | `/` | `CreateSysModuleTableReq` | `SysModuleTableEntryResp` |
| 详情 | GET | `/{tableId}` | - | `SysModuleTableDetailResp` |
| 获取 | GET | `/module/{moduleId}` | - | `List<SysModuleTableEntryResp>` |
| 查询 | POST | `/query` | `QuerySysModuleTableReq` | `List<SysModuleTableEntryResp>` |
| 更新 | PUT | `/{tableId}` | `UpdateSysModuleTableReq` | `SysModuleTableEntryResp` |
| 删除 | DELETE | `/{tableId}` | - | `Void` |
| 批删 | POST | `/batch-delete` | `List<Long>` | `Void` |

### 字段配置与元数据 (`/api/config/tables`)

| 操作 | HTTP | 端点 | 参数 | 职责 |
|------|------|------|------|------|
| 获取所有表 | GET | `/tables` | - | 获取当前项目库的所有表元数据 |
| 获取列信息 | GET | `/tables/{tableName}/columns` | `tableName` | 获取列元数据及已保存的字段配置 |
| 保存配置 | POST | `/fields` | `SysFieldSaveReq` | 保存或更新特定字段的显示逻辑 |

## 关键特性

### 1. 多租户与项目路由
- **统一 Header**: 使用 `X-Project-No` 传递项目编号。
- **上下文绑定**: 由 `AppContextInterceptor` 自动提取并绑定到线程上下文。
- **参数原则**:
    - **读操作 (Query)**: API 接口显式定义 `projectNo` 参数，确保查询条件的严谨。
    - **写操作 (Write)**:
        - 若请求体或路径中包含主键 `id`，接口不体现 `projectNo`，内部通过 `selectById` 操作。
        - 新增记录时，Service 内部通过 `AppContext.getProjectNo()` 获取并填充 `tenant_id` 字段。

### 2. 逻辑删除
- 使用 `deleted` 字段标记删除
- 查询时自动过滤已删除数据

### 3. 审计字段
- `created_by`, `created_date`, `created_name`
- `updated_by`, `updated_date`, `updated_name`
- 自动记录操作人和操作时间

### 4. 权限位运算
- READ (1) - 读权限
- CREATE (2) - 创建权限
- UPDATE (4) - 更新权限
- 权限值范围 0-7

### 5. 树形结构
- 模块支持树形结构
- 通过 `parent_id` 和 `module_path` 实现

```bash
X-Project-No: school
Content-Type: application/json

{
  "module": {

    "moduleName": "学生列表",
    "moduleType": "LIST"
  },
  "simpleFields": [...]
}
```

```bash
GET /api/config/tables/student/columns
X-Project-No: school
```
